# Журнал изменений

Формат — по https://keepachangelog.com/ru/1.1.0/, версии — по https://semver.org/lang/ru/.

## [0.1.0] — 2026-09-16

Первый открытый выпуск.

### Добавлено

- MCP-сервер `yaseo-mcp` на стандартной библиотеке Python, без внешних зависимостей.
- 18 инструментов ядра: `whoami`, `research_keywords`, `get_keyword_metrics`, `get_serp_results`, `find_serp_competitors`, `get_competition`, `build_brief`, `expand_query_pool`, `track_query`, `run_tracking`, `get_positions`, `get_position_history`, `get_competitor_keywords`, `audit_site`, `check_articles`, `get_article_effectiveness`, `get_storage_stats`, `get_action_plan`.
- Инструмент MCP `get_action_plan` и команда `yaseo plan`: план правок сайта по названным правилам. Порядок разделов: индексация, быстрые выигрыши (по Вебмастеру позиция 4–15, по трекеру 4–10: трекер снимает топ-10), сниппет (показы без кликов), каннибализация, ИИ-поиск, разрывы с конкурентами, остальное. В каждом пункте — доказательство с источником и датой, инструкция для Claude или разработчика, способ проверки и срок, раньше которого эффект не проверять. Платных запросов инструмент не делает. Если данных нет, он называет инструмент и смету.
- Видимость в ИИ-поиске (GEO): `geo_readiness` (без ключей), `geo_providers`, `geo_check_visibility` (смета без `confirm`; трата только с `confirm=true` и явным списком `providers`), `geo_history`. Провайдеры: генеративный ответ Яндекса, Perplexity, OpenAI, Gemini, Claude.
- Команда `yaseo` с подкомандами `init`, `serp`, `keywords`, `competition`, `pool`, `core`, `brief`, `track`, `articles`, `audit`, `plan`, `webmaster`, `metrika`, `yandex`, `storage`, `mcp`.
- `yaseo init`: пошаговый ввод ключей в `~/.config/yaseo/.env` с доступом только для владельца, бесплатная проверка и, по согласию, одна живая.
- Позиции трекера — медиана снимков там, где вообще есть из чего её брать: фраза, уже видевшая топ (или новая), снимается несколько раз, фраза без топа в прошлый замер — один раз. Потолок обращений за прогон (`YASEO_TRACKING_MAX_CALLS`), смета перед платными прогонами.
- Потолок обращений и смета до траты — тем же способом, что у трекера позиций — теперь и у `check_articles`/`yaseo articles --check`: настройка `articles_max_calls` и переменная `YASEO_ARTICLES_MAX_CALLS` (по умолчанию 100), останов ДО первого запроса с человеческим объяснением, `yaseo articles --check --dry` печатает смету и ничего не тратит.
- Смета трекера и проверки статей учитывает постраничный набор выдачи: глубина набирается страницами по 10 (`estimate.pages_for_depth`, делегирует `yandex_serp.pages_for`), топ-30 стоит 3 обращения на снимок, а не одно; глубина ограничена 50.
- Общий сетевой транспорт `net.py`: запросы с ключом или токеном уходят только по https и не следуют за перенаправлениями — ключ не может утечь на чужой домен через редирект. Аудит и проверка готовности к ИИ-поиску ходят только по http/https, к приватным и внутренним адресам (localhost, `10.0.0.0/8`, `192.168.0.0/16` и подобным) — только с явным разрешением: `YASEO_ALLOW_PRIVATE=1` или флаг `--allow-private` у `yaseo audit` и `yaseo plan`.
- Содержимое сайтов при аудите и ответы ИИ-провайдеров при проверке видимости помечаются в выводе как данные, а не инструкции: агент, читающий ответ MCP, не выполняет то, что «попросила» чужая страница.
- Аудит: карты сайта (sitemap.xml) читаются только со своего домена, с новыми кодами находок `sitemap-foreign-host` и `sitemap-too-large`; распаковка сжатой карты ограничена 50 МБ несжатых данных.
- Плагин Claude Code: маркетплейс `yaseo`, плагин `yaseo`, семь скиллов: `yaseo-setup`, `seo-site-check`, `keyword-research`, `position-tracking`, `content-brief`, `improve-positions`, `ai-visibility` — план, выбор пунктов человеком, исполнение по одному пункту с диффом, бесплатная проверка после правок.
- Документация: `README.md`, `docs/INSTALL.md` (пошаговая установка), `docs/KEYS.md` (ключи и настройки).

### Исправлено

- Адреса с пробелом, кириллицей в пути или в запросе (`/o kompanii/`, `/о-компании/`) аудит считал недоступными (ложная critical `page-unavailable`), а проверка готовности к ИИ-поиску падала. Теперь все запросы к сайтам проходят через одну функцию `net.safe_url`: домен переводится в IDNA, путь и запрос кодируются по RFC 3986, уже закодированное `%XX` второй раз не кодируется, якорь отбрасывается. Сетевые сбои (`http.client.HTTPException`, `OSError`) возвращаются причиной без трейсбека; проверка готовности один раз повторяет запрос после обрыва соединения.
- Адрес страницы в плане (`**Страница:**`) и в таблицах `audit_site` и `geo_readiness` печатается percent-кодированным: он совпадает с адресом на сайте и не превращается в разметку Markdown.
- «Сбой инструмента» в MCP больше не отдаёт трейсбек: только тип исключения и последние кадры (файл, строка, функция), под пометкой о внешних данных.
- У `yaseo plan` появился флаг `--allow-private`; текст отказа по внутреннему адресу называет все способы разрешения.
- Плагин в `marketplace.json` и команды `uvx` в плагине закреплены на теге `v0.1.0`.
- При чётном числе снимков позиции трекер усреднял реальную позицию с «нет в топе»: `[5, None]` давал медиану 5002 — число без смысла, которое уходило в историю и в отчёт как настоящая позиция. Теперь чётная длина берёт нижнюю медиану (фактически увиденное значение, а не выдуманное среднее), а если один из двух центральных снимков сам «нет в топе», результат — тоже «нет в топе», консервативно и объяснимо.
- Запись файла ключей (обновление токена, `write_env_value`, `yaseo init`) обнуляла файл и писала заново; падение между этими шагами (например, обрыв во время продления OAuth-токена) оставляло файл пустым, и параллельный MCP-сервер читал ноль ключей вместо старых. Запись теперь атомарна: временный файл рядом, `fsync`, `os.replace` — снаружи виден либо старый файл целиком, либо новый.
- У `check_articles`/`yaseo articles --check` не было потолка: число статей и дополнительных запросов ничем не ограничивалось, и прогон мог потратить сколько угодно без предупреждения (потолок и смета — см. «Добавлено» выше).
- Отказ источника целиком (например, неверный ключ Яндекса, HTTP 401) приходил клиенту MCP обычным текстом «ОШИБКА …» без `isError`, и агент читал его как успешный ответ. Теперь такие ответы помечены `isError: true`, причина передаётся дословно. Это касается `get_serp_results`, `research_keywords`, `get_keyword_metrics`, `find_serp_competitors`, `get_competition`, `build_brief`, `expand_query_pool`, `run_tracking`, `check_articles`, `audit_site` и `geo_check_visibility`. Если часть пакета упала, это по-прежнему не ошибка: упавшие запросы перечисляются вместе с причиной.
- «Последнее окно» Вебмастера и Метрики выбиралось по одному `MAX(date_to)`. Две выгрузки за день с разным `--days` дают окна с общим концом, поэтому запрос печатался дважды, а суммы складывали окна разной длины. Теперь последним считается одно окно — выгруженное последним (при равной отметке — более длинное). То же исправлено в сводке `get_storage_stats`: она теперь берёт последнее окно отдельно для каждого хоста.
- Аудит склеивал текст `<h1>` из соседних элементов без пробела: `<span>Маркетинг</span><span>застройщика</span>` цитировался как «Маркетингзастройщика». Теперь текстовые узлы разделяются пробелом.
- Ключи ИИ-провайдеров (`PERPLEXITY_API_KEY`, `OPENAI_API_KEY`, `GEMINI_API_KEY`, `ANTHROPIC_API_KEY`) теперь читаются из окружения процесса наравне с ключами Яндекса — раньше `read_all()` знал про окружение только для Яндекса и `YASEO_*`, и провайдер, ключ которого задан лишь переменной, показывался «не настроен». `geo_providers` и `whoami` показывают источник каждого ключа.
- Цепочка поиска ключей больше не читает `./.env` текущего каталога: MCP-сервер запускается из каталога любого проекта пользователя, и чужой `.env` (ключи другого проекта) молча подхватывался под видом своих. Новая цепочка: окружение процесса → `$YASEO_ENV_FILE` → `$XDG_CONFIG_HOME/yaseo/.env`.
- `run_tracking` при остановке до первого запроса (по потолку `YASEO_TRACKING_MAX_CALLS` или по сроку `YASEO_TRACKING_MIN_INTERVAL_DAYS`) отвечал в MCP невнятным «Прогон -1: снято 0 из N» без причины. Теперь ответ — та же человеческая причина, что печатает CLI: сколько обращений нужно, какой потолок или срок, как его снять на этот раз (параметр `now`). Срок между прогонами по домену теперь держит и MCP-инструмент `run_tracking`, не только `yaseo track --run`.
- README называл шесть скиллов вместо семи (не хватало `improve-positions`), «медиану трёх снимков» вместо переменного числа снимков по горячим/холодным фразам, и не объяснял, у каких платных инструментов смета и потолок держит код, а у каких — только скилл-агент. Уточнено там же и в таблице инструментов, с колонкой «тратит», учитывающей постраничную глубину.

### Известные ограничения

- Вебмастер и Метрика доступны из командной строки, среди инструментов MCP их нет.
- Пакет не опубликован в PyPI, установка идёт из GitHub через `uvx` или `uv tool install`.
- Аудит не открывает сайты, заданные IPv6-адресом вместо имени (`http://[…]/`).
- За прокси в режиме fake-ip (`198.18.0.0/15`) имена сайтов не проверяются на внутренние адреса; адреса-числа отсекаются всегда. Внутри IPv6 (NAT64, 6to4) проверяется зашитый IPv4-адрес.
