# yaseo

Open-source SEO and AI-search visibility toolkit for Yandex (Russian web), packaged as an MCP server and a Claude Code plugin.

**SEO и видимость в ИИ-поиске для сайтов в рунете, прямо в вашем Claude.**

yaseo — набор инструментов, которые Claude вызывает сам: частотность из Wordstat, живая выдача Яндекса, позиции с историей, технический аудит, бриф статьи, проверка, цитирует ли сайт ИИ-поиск. Работает на ваших ключах Яндекса, а для проверки ИИ-поиска — по желанию — ещё и на ключах ИИ-провайдеров. Код открытый, пользоваться бесплатно, лицензия MIT.

Разговор выглядит так:

> Проверь, настроен ли yaseo.
> Проверь мой сайт example.ru.
> Собери семантику для раздела «ремонт квартир».
> Цитирует ли ИИ-поиск example.ru по запросу «где заказать ремонт»?
> Дай план, как поднять позиции example.ru.

Пошаговая установка для тех, кто впервые открывает терминал: **[docs/INSTALL.md](docs/INSTALL.md)**.

## Что умеет

**Семантика.** Частотность по Wordstat, расширения исходной фразы (уточнения и похожие запросы), подбор кандидатов в пул отслеживания с причиной по каждому.

**Выдача и конкуренты.** Живая выдача Яндекса по запросу; кто повторяется в топе по набору запросов (с делением на сайты и крупные площадки); конкурентность запроса с разбором по факторам; по каким запросам конкурент стоит в топе, а вас рядом нет.

**Позиции.** Отслеживание запросов, замеры с историей, выросшие и просевшие запросы, история по одному запросу.

**Технический аудит.** Индексация, метаданные, заголовки, канонические адреса, разметка, перелинковка. Каждая находка приходит с доказательством и советом, что сделать.

**Статьи и каннибализация.** Бриф перед статьёй по составу топа. Замер статей блога показывает, вышла ли именно эта статья или вместо неё другая страница сайта.

**Вебмастер и Метрика.** Показы, клики и индексация от владельца сайта, поведение на посадочных страницах. Нужен OAuth-токен Яндекса. Выгружаются из командной строки (`yaseo webmaster`, `yaseo metrika`). Среди инструментов MCP отдельной выгрузки нет, но `get_action_plan` читает уже выгруженное из базы.

**План действий.** Список правок сайта по приоритету: у каждой правки есть доказательство с датой, готовая инструкция для Claude или разработчика и способ проверки. Подробнее — в разделе [План действий](#план-действий).

**Видимость в ИИ.** Готовность сайта к ИИ-поиску без ключей: `llms.txt`, доступ ИИ-ботов в robots.txt, JSON-LD, FAQ-разметка. Проверка, цитируют ли сайт генеративный ответ Яндекса, Perplexity, OpenAI, Gemini и Claude, каким адресом и кого цитируют вместо него.

## Как устроен

- **Данные Яндекса берутся у самого Яндекса.** Wordstat и выдачу yaseo получает через официальный Yandex Search API, с регионами Яндекса (по умолчанию вся Россия).
- **Позиция трекера — медиана снимков, там, где вообще есть из чего её брать.** Одинаковые запросы подряд могут дать 11, 6 и 5 место, поэтому фраза, которая уже была в топе (или новая), снимается несколько раз (по умолчанию трижды). Фраза, которой в топе не было, снимается один раз: три «нет в топе» подряд не добавили бы ничего к первому. У «холодных» фраз, соответственно, снимок один. Трекер по умолчанию смотрит топ-10.
- **У каждой находки есть доказательство.** Аудит, конкурентность и бриф показывают, на чём основан вывод.
- **«Нет данных» вместо выдуманного числа.** Если источник промолчал, yaseo так и пишет.
- **Смета встроена не везде одинаково.** `run_tracking`, `check_articles` и `geo_check_visibility` сами считают число обращений и останавливаются до траты, если вышло больше потолка (или без вашего `confirm` — для проверки ИИ-поиска). У остальных платных инструментов смету перед вызовом называет не код, а скилл-агент — подробности в разделе [Инструменты MCP](#инструменты-mcp).
- **Данные лежат у вас.** Всё накопленное хранится в локальной базе SQLite.
- **Сделан под агента.** MCP-сервер на чистом Python без внешних зависимостей, только стандартная библиотека.

## Установка

Нужны [Claude Code](https://code.claude.com/docs/en/setup) и [uv](https://docs.astral.sh/uv/getting-started/installation/). Подробно, с проверкой на каждом шаге: [docs/INSTALL.md](docs/INSTALL.md).

### 1. Плагин Claude Code (основной путь)

В Claude Code:

```
/plugin marketplace add novyiblog-tech/yaseo
/plugin install yaseo@yaseo
```

Плагин подключает MCP-сервер `yaseo` и семь скиллов: `yaseo-setup`, `seo-site-check`, `keyword-research`, `position-tracking`, `content-brief`, `improve-positions`, `ai-visibility`. Сервер запускается командой `uvx --from git+https://github.com/novyiblog-tech/yaseo@v0.1.1 yaseo-mcp`, поэтому на компьютере должен быть `uv`.

Затем ключи:

```
uvx --from git+https://github.com/novyiblog-tech/yaseo@v0.1.1 yaseo init
```

### 2. Только MCP-сервер через uvx

Для Claude Code без плагина или другого MCP-клиента:

```
claude mcp add --transport stdio yaseo -- uvx --from git+https://github.com/novyiblog-tech/yaseo@v0.1.1 yaseo-mcp
```

В других клиентах укажите команду `uvx` с аргументами `--from git+https://github.com/novyiblog-tech/yaseo@v0.1.1 yaseo-mcp`.

Постоянная команда `yaseo` в терминале:

```
uv tool install git+https://github.com/novyiblog-tech/yaseo@v0.1.1
yaseo --help
```

### 3. Из исходников

```
git clone https://github.com/novyiblog-tech/yaseo
cd yaseo
uv run yaseo --help
uv run yaseo-mcp < /dev/null   # сервер стартует и сразу выходит: проверка запуска
```

Проверка сервера вручную:

```
echo '{"jsonrpc":"2.0","id":1,"method":"tools/list"}' | uv run yaseo-mcp
```

## Ключи

Обязательны два значения: `YC_FOLDER_ID` и `YANDEX_AI_STUDIO_API_KEY` из Yandex AI Studio. Остальные ключи необязательные: Вебмастер и Метрика, ИИ-провайдеры. Где взять каждый ключ, где он хранится и как его сменить: **[docs/KEYS.md](docs/KEYS.md)**.

Ключи ваши, и платите за обращения тоже вы: Яндекс берёт плату по своему прайсу (https://aistudio.yandex.ru/ru/docs/search-api/pricing), зарубежные провайдеры — по тарифу вашего аккаунта. yaseo показывает смету до траты. Одна цифра для ориентира: генеративный ответ Яндекса заметно дороже обычной выдачи, на 16.09.2026 это 5 080 ₽ за 1 000 запросов.

## Инструменты MCP

«Тратит» — к какому платному API обращается инструмент и сколько раз за один вызов. Инструменты с пометкой «нет» либо читают локальную базу, либо ходят только на ваш сайт. Там, где обращений больше одного из-за глубины выдачи (параметр `n` или `depth`), глубина набирается страницами по 10: топ-10 — 1 обращение, топ-30 — 3, топ-50 (потолок) — 5.

| инструмент | что делает | тратит |
|---|---|---|
| `whoami` | откуда взяты ключи, чего не хватает, где база, домен по умолчанию | нет |
| `research_keywords` | расширить 1–5 фраз через Wordstat: частотность и связанные запросы | Wordstat, 1 на фразу |
| `get_keyword_metrics` | частотность и конкурентность до 25 запросов | Wordstat и Search API, по 1 на запрос |
| `get_serp_results` | живая выдача Яндекса по запросу | Search API, по страницам глубины `n` (умолчание топ-10 — 1) |
| `find_serp_competitors` | кто повторяется в выдаче по набору до 10 запросов | Search API, 1 на запрос |
| `get_competition` | конкурентность с разбором по факторам и доказательствами | Search API, 1 на запрос |
| `build_brief` | разведка перед статьёй: топ, форматы, разрывы, подзапросы | Wordstat 1, Search API по страницам глубины `n` (умолчание топ-10 — 1) |
| `expand_query_pool` | кандидаты в пул отслеживания с причиной; запись при `apply=true` | Wordstat, 1 |
| `track_query` | поставить запросы на отслеживание или снять | нет |
| `run_tracking` | снять позиции по отслеживаемым запросам и записать в историю; останавливается до первого запроса и объясняет почему, если обращений вышло бы больше потолка (`YASEO_TRACKING_MAX_CALLS`) или домен мерили недавно (снять на раз — `now=true`) | Search API, до 3 снимков на запрос × страниц глубины (умолчание топ-10 — 1 обращение на снимок) |
| `get_positions` | текущие позиции, изменение к прошлому замеру | нет |
| `get_position_history` | история позиций по запросу и динамика конкурентности | нет |
| `get_competitor_keywords` | где конкурент в топе, а вас нет, по накопленным снимкам | нет |
| `audit_site` | технический аудит сайта; только http/https, приватные адреса — только с `YASEO_ALLOW_PRIVATE=1` | нет |
| `check_articles` | замер статей блога: вышла ли именно эта статья; останавливается до первого запроса и объясняет почему, если обращений вышло бы больше потолка (`articles_max_calls`/`YASEO_ARTICLES_MAX_CALLS`) | Search API, по страницам глубины на уникальный запрос — запрос нескольких статей стоит один раз, а не по разу за каждую |
| `get_article_effectiveness` | отчёт по статьям и список каннибализаций | нет |
| `get_storage_stats` | что накоплено в базе | нет |
| `get_action_plan` | план правок сайта по приоритету: доказательство, инструкция для Claude, способ проверки | нет: HTTP только к самому сайту, остальное из базы |
| `geo_readiness` | готовность сайта к ИИ-поиску; только http/https, приватные адреса — только с `YASEO_ALLOW_PRIVATE=1` | нет |
| `geo_providers` | какие ИИ-провайдеры настроены и каких ключей не хватает | нет |
| `geo_check_visibility` | цитирует ли ИИ-поиск сайт; без `confirm` только смета | только с `confirm=true` и списком `providers` |
| `geo_history` | история проверок видимости: доля цитирований, частые конкуренты | нет |

**Смета — где в коде, где в скилле.** Встроенную смету и потолок, с остановкой ДО первого платного запроса, держат в самом коде только три инструмента: `run_tracking`, `check_articles` и `geo_check_visibility` (последний — просто ничего не тратит без вашего `confirm`). Остальные платные инструменты — `get_keyword_metrics` (до 25 запросов к Search API и Wordstat), `get_serp_results`, `find_serp_competitors`, `get_competition`, `build_brief`, `research_keywords`, `expand_query_pool` — тратят сразу, как только их вызвали: своего тормоза в коде у них нет, а смету перед вызовом называет не код, а скилл-агент.

Про провайдера `yandex` в `geo_check_visibility`: это генеративный ответ YandexGPT по результатам Поиска (`POST /v2/gen/search` в Yandex Search API), а не сама «Нейро» или Алиса. У каждого источника в ответе есть признак `used`. «Источник показан» и «источник использован в ответе» — разные вещи: в живом прогоне 16.09.2026 из 5 источников использованы были 3. Процитированным yaseo считает сайт, только если его источник использован.

## План действий

`get_action_plan` (в терминале — `yaseo plan --domain example.ru`) собирает список правок сайта из того, что уже измерено или проверяется бесплатно. Это технический аудит, готовность к ИИ-поиску, история позиций, выгрузки Вебмастера, реестр статей и накопленные снимки выдачи. Новых платных запросов инструмент не делает. Чего нет в базе, того нет и в плане: вместо пункта он называет инструмент, который даст данные, и его смету.

Порядок задают названные правила, общего балла нет:

1. **Индексация** — критичные находки аудита: страница не отдаётся, битая внутренняя ссылка, цепочка редиректов, noindex или Disallow у адреса из sitemap.xml. Сюда же — robots.txt, который не отдаётся.
2. **Быстрые выигрыши** — запрос уже показывается не на верхних местах: по Вебмастеру — средняя позиция 4–15, по трекеру — позиция 4–10, потому что трекер снимает топ-10 (для трекера нужен известный спрос). Страницу доводят под запрос; текущие title и H1 процитированы.
3. **Сниппет** — не меньше 30 показов, ноль кликов, позиция не ниже 10-й.
4. **Каннибализация** — две страницы сайта претендуют на один запрос.
5. **ИИ-поиск** — robots.txt закрывает ИИ-ботов, нет `llms.txt`, нет JSON-LD. Запрет Google-Extended на Google Поиск не влияет, план так и пишет.
6. **Разрывы с конкурентами** — конкурент есть в накопленной выдаче по запросу с известной частотностью, а у сайта страницы под этот запрос нет.
7. **Остальное** — прочие находки аудита, по одному пункту на вид.

В каждом пункте: страница; что сейчас (цитата или число, источник, дата замера); что сделать; блок «Инструкция для Claude», который можно передать своему Claude или разработчику; как проверить после; когда ждать эффекта. Позиции предлагается переснимать не раньше срока из настроек трекера. Рост позиций план не обещает.

Параметры: `domain`, `url` (адрес для аудита), `max_pages` (по умолчанию 30), `sections` (какие разделы собрать), `limit` (по умолчанию 10 пунктов, остальные сворачиваются в счётчик по разделам) и `fresh_audit`. По умолчанию аудит проводится заново, если в базе его нет или ему больше 7 дней. Свежий аудит сохраняется в базу.

Разбор плана и исполнение по одному пункту описаны в скилле `improve-positions`.

## Настройки

| переменная | что задаёт | по умолчанию |
|---|---|---|
| `YASEO_DOMAIN` | домен сайта для «наших» позиций | не задан; если в базе один проект, берётся его домен |
| `YASEO_DB` | путь к базе SQLite | `~/.local/share/yaseo/yaseo.db` |
| `YASEO_ENV_FILE` | свой файл с ключами | не задан |
| `YASEO_USE_PROXY` | `1` — ходить к Яндексу через системный прокси | `0`: к Яндексу напрямую |
| `YASEO_TRACKING_MAX_CALLS` | потолок обращений к Search API за один прогон позиций | `1000` |
| `YASEO_TRACKING_MIN_INTERVAL_DAYS` | сколько суток между прогонами по одному домену; держат и `yaseo track --run`, и MCP `run_tracking` — снять срок на один раз: `--сейчас` в CLI, `now=true` в MCP | `13` |
| `YASEO_TRACKING_FILE` | файл настроек трекера | `~/.config/yaseo/tracking.json` |
| `YASEO_ARTICLES_MAX_CALLS` | потолок обращений к Search API за один прогон `check_articles`/`yaseo articles --check` | `100` |
| `YASEO_ALLOW_PRIVATE` | `1` — разрешить аудиту и проверке готовности к ИИ-поиску ходить на внутренние адреса (localhost, `10.0.0.0/8`, `192.168.0.0/16` и подобные); у `yaseo audit` и `yaseo plan` то же самое делает флаг `--allow-private` | `0`: отказ |
| `YASEO_RATES` | свой файл тарифов для сметы | встроенный `rates.json` |
| `YASEO_RATE_SEARCH_API`, `YASEO_RATE_WORDSTAT` | ставка за одно обращение, в рублях, для сметы | из `rates.json` |

Каталоги данных следуют `XDG_DATA_HOME` и `XDG_CONFIG_HOME`, если они заданы.

## Безопасность

Свойства версии 0.1.1:

- **Внешние данные показываются как данные, а не как команды.** Содержимое сайтов при аудите и ответы ИИ-провайдеров при проверке видимости идут в вывод отдельным, явно подписанным блоком; инструкции внутри них не выполняются.
- **Ключ не уходит на чужой домен.** Запросы с ключом или токеном идут только по https и не следуют за перенаправлениями — это держит общий сетевой слой пакета (`net.py`).
- **Сканер ходит только по http и https.** К приватным и локальным адресам (localhost, `10.0.0.0/8`, `192.168.0.0/16` и подобным) — только с явным разрешением: `YASEO_ALLOW_PRIVATE=1` или флаг `--allow-private` у `yaseo audit` и `yaseo plan`. По умолчанию — отказ. Адреса-числа (`127.0.0.1`, `[::1]`, `10.0.0.5`) отсекаются всегда, а имена сайтов проверяются по их DNS-адресу, и за прокси в режиме fake-ip (адреса `198.18.0.0/15`) такая проверка не работает: любое имя получает подставной адрес.

## Приватность

Куда уходят данные:

- **Яндекс** (`searchapi.api.cloud.yandex.net`): ваши запросы для Wordstat, выдачи и генеративного ответа, с вашим ключом.
- **Яндекс ID, Вебмастер, Метрика** (`oauth.yandex.ru`, `api.webmaster.yandex.net`, `api-metrika.yandex.net`) — только если вы подключили OAuth. Проверка токена `yaseo yandex --check` дополнительно спрашивает API Директа (`api.direct.yandex.com`), чтобы сказать, открыт ли он токену.
- **ИИ-провайдеры** (`api.perplexity.ai`, `api.openai.com`, `generativelanguage.googleapis.com`, `api.anthropic.com`) — только если вы положили их ключ, выбрали провайдера и подтвердили проверку. Уходит текст запроса. Для Gemini yaseo дополнительно раскрывает ссылки-переадресации источников запросом `HEAD`.
- **Сайты, которые вы проверяете**: аудит и проверка готовности к ИИ читают их страницы.

Телеметрии нет. yaseo не отправляет сведений о себе, о вас или о вашей работе никуда, кроме перечисленных адресов. Это можно проверить по коду: все сетевые обращения идут через общий транспорт `net.py`, а вызывают его `yandex_serp.py`, `wordstat_client.py`, `yandex_auth.py`, `audit.py`, `geo/providers.py` и `geo/readiness.py`.

Что хранится у вас:

- ключи — `~/.config/yaseo/.env`, доступ только владельцу;
- база — `~/.local/share/yaseo/yaseo.db`: снимки выдачи, позиции, статьи, ответы ИИ-провайдеров (текст ответа и исходный ответ API);
- снапшоты Wordstat и отчёты — рядом с базой, в `~/.local/share/yaseo/`.

Ключи не печатаются целиком ни в одном выводе.

## Ограничения

- **Ссылочного веса нет.** Конкурентность считается по составу выдачи, ссылки yaseo не видит.
- **Глубина выдачи — не больше топ-50.** Глубже позиции для задач пакета ничего не решают, а цена растёт линейно: каждые 10 мест — ещё одно платное обращение.
- **Wordstat: 100 запросов в час** по квоте Яндекса. Большие списки надо делить на части.
- **Ноль в Wordstat не доказывает, что спроса нет.** Редкие формулировки Wordstat может не показать.
- **Генеративный ответ Яндекса дорогой** и принимается не чаще одного запроса в секунду.
- **Ответы ИИ меняются.** Один прогон — это снимок. Устойчивую картину дают повторы и история.
- **Провайдер `yandex` — не «Нейро».** Это генеративный ответ по результатам Поиска из Search API.
- **Вебмастер и Метрика** пока доступны только из командной строки.
- **Лимиты и цены Яндекса меняются.** Сверяйтесь с https://aistudio.yandex.ru/ru/docs/search-api/concepts/limits и https://aistudio.yandex.ru/ru/docs/search-api/pricing.
